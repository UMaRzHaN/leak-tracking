# Реестр компонентов — передача работы

Ветка `claude/component-registry`, отведена от `claude/import-worker` (та на 527
коммитов впереди `main`, поэтому не от `main`). 22 коммита, последний `f34553a`.

Всё, что ниже, — состояние на конец предыдущей сессии. Проверки на момент
передачи зелёные:

```bash
npm run lint && npm run typecheck && npm run format:check && npx vitest run && npm run build && npm run check:bundle
```

1931 тест, из них ~150 новых. Индексный чанк 361 862 при лимите 368 640.

---

## 1. Что это за фича

Инвентаризация оборудования — **отдельный процесс от учёта утечек**. Сколько на
месторождении задвижек, вентилей и манометров, никто не знает; исходный файл
заказчика (`Database component.xlsx`) — не реестр, а шаблон и прикидка. Реальная
работа: человек идёт по площадке, находит железо, **присваивает ему номер**,
заполняет карточку, фотографирует. Реестр рождается в поле.

**Компонент — постоянный объект учёта, утечка — событие на нём.** Не наоборот.

Кампания разовая, режима повторного обхода нет.

## 2. Ключевые архитектурные решения и почему

Эти решения приняты не наугад — переспорить их можно, но сначала прочитайте
причину.

### Вторая сущность соседним блоком, а не общей формой

Форма конфига проекта односущностная: `config.system`, `config.steps`,
`config.export` молча означают «утечка», и на этом построен весь
`projectAdapter.js` плюс шесть мест, читающих конфиг напрямую. Поэтому реестр
объявлен **соседним блоком** `config.components` — существующий код не тронут.

Отсутствие блока = реестра у потока нет. Фича-флаг бесплатно, в стиле,
заявленном в комментарии адаптера: никаких сравнений по типу проекта.

Сейчас блок есть **только у upstream** — исходник заказчика покрывает добычу.

### Блок грузится лениво

`components: { load: () => import("./data/componentBlock") }`. Конфиг проекта
лежит в стартовом чанке; словари оборудования и четыре шага формы — это ~11 КБ
данных для экрана, который большинство сессий не открывает. Инлайновое
объявление **ломало бюджет сборки** (372 420 при лимите 368 640).
`hasComponentRegistry` осталась синхронной — её дёргает нижняя навигация на
каждом рендере.

### Хранение отдельным ключом

Своя IndexedDB (`LeakTrackingComponentsDB`), на нативе свой файл
`LeakReports/<folder>/data/components.json`. Контейнер утечек читается целиком
при каждом старте; тысячи карточек в нём затормозили бы запуск.

### Идентичность

Два номера, роли разные:

- **Инвентаризационный номер на схеме** (`scheme_tag`) — метка с чертежа,
  `ЗД32`, `PG`. **Не уникальна**: в исходнике `ЗД32` дважды, `PG` десятки раз.
- **Индивидуальный номер** (`component_uid`) — цифры, присваивает обходчик,
  уникален **по договорённости людей**, не по построению.

Первичный ключ — UUID. Бирки перебивают, номера правят; правка номера не должна
рвать ссылки.

**Приложение уникальность предполагает, а не обеспечивает.** Диапазоны не
раздаются (решение заказчика), чужие номера не видны. Отсюда: подсказка не
навязывает, дубль предупреждает но не блокирует, совпадение с другого устройства
показывается как конфликт при сведении. Сквозные цифры при параллельном обходе
совпадут гарантированно — экран разбора конфликтов это основной инструмент, а не
запасной.

### Общие ключи с утечкой

`object`, `component`, `actuator_type`, `connection_type`, `installation_type`,
`lat`, `lng`, `photo` — те же ключи. Это не экономия: будущая ссылка утечки на
компонент станет прямым копированием, а не таблицей соответствий.

Намеренно **не** переиспользованы `pressure` и `temperature`: у утечки это замер
в атм и °C, у компонента паспортные МПа. Один ключ тихо смешал бы две единицы.

### Переиспользование, а не свои компоненты

Это стоило трёх переделок за сессию. **Сначала ищите существующий компонент.**

Уже переиспользовано: `StepRenderer`, `InputCard`, `PageHeader`,
`AddLeakFooter`, `ClearActions`, `LeakForm.module.scss`, `LeakDetailsSheet`
(вместе с его таблицей стилей), `PhotoBlock`, `PhotoViewer`, `viewBlockUtils`,
`useSwipeActions`, `usePhotoSrc`, `usePhotoStorage`, `VirtualizedLeakList`,
`ConfirmSheet`, `useModalDialog`, `matchesLeakLocationFilter`,
`getCopyPreviousKeys`, `buildLeakHistoryChanges`, `requireHistoryUser`.

### Подпись обходчика

Ничего не пишется без имени в профиле. `requireHistoryUser` бросает вместо
подстановки «неизвестно». Реестр, который никто не подписывает, — список
утверждений без людей за ними.

## 4. Что сделано

- Реестр как вторая сущность, форма в 4 шага, список, поиск, фильтры
- Технологические схемы: загрузка, хранение, просмотрщик, папка в архиве в обе
  стороны
- Выгрузка листом «Компоненты» в тот же `!Database_<проект>.xlsx`
- Сведение реестров между устройствами с разбором конфликтов
- Компактная карточка с фото, свайпы, подробная карточка на компоненте утечки
- История: заведение, правка, осмотр; подпись обходчика обязательна
- Геопривязка (снимается молча), дата монтажа календарём, дата инспекции
  выводится
- Настройка «фото обязательно» для реестра рядом с утечкой и мониторингом
- Виртуализация списка, место из общего фильтра шапки, фильтр по состоянию

## 5. Известные дыры — читать перед работой

### Снимки компонентов не попадают в архив

Папка `photos/` собирается обходом **утечек** (`excel.js:38`).
`components.json` везёт пути `idb://…`, которые на другом устройстве пусты.
**Тихая потеря данных при переносе.** Чинить как схемы: своя папка, подмена пути
на имя файла при выгрузке, запись в хранилище при разборе.

### Голый .xlsx теряет реестр

Лист объявлен `direction: ["export"]` и обратно не читается. ZIP довозит реестр
отдельным `components.json`.

**Импорт утечек при этом НЕ сломан** — проверено: `findLeakSheet`
(`workbookSchema.js:297`) выбирает лист по точному совпадению заголовка с
синонимами `leak_id`, а «Индивидуальный номер компонента» среди них нет.

### Геолокация не как у утечки

`AddLeak.jsx:201`: если координат нет — приёмник включается сам, форма ждёт фикс,
и только потом сохраняет без координат с честным сообщением. Карточка компонента
снимает фикс молча при открытии и пишет пусто.

### Голосовой ввод не заполняет

Кнопка стоит и запускает распознавание, но у реестра нет своего `voice`-блока в
конфиге — писать некуда. Так и было задумано на том шаге («пока не дорабатывать»).

### Старые карточки

Заведённые до слияния полей показываются как «Без наименования»: ключ был
`component_name`, стал `component`. Тестовых проще перезавести; если появятся
реальные данные — нужна миграция.

### Отдельной задачей висит

Словарь наименований в `src/data/leak/fieldDictionary.js`: опечатки
(«Маноментр», «Дросель», «Уровномер», «Газораспределетельный пункт») и
расхождения с реестром («Клапан обратный» против «Обратный Клапан»). Причёсывать
надо **до** начала реального обхода, иначе разнобой закрепится навсегда.

## 6. Очередь работ

Порядок предложен: 1–3 про данные и их сохранность, остальное интерфейс.

1. **Экспорт инвентаризации отдельным архивом** — кнопка на странице реестра,
   архив с `Photos`, `Schemes`, `!Inventorization/` и XLSX с листом
   `Inventorization`. Сюда же чинить снимки в архиве.
2. **Импорт: автоопределение типа файла и базы** — XLSX, ZIP Backup, QR;
   пользователь не выбирает тип вручную. Научить читать лист `Inventorization`.
3. **Синхронизация и структура папок на Android** — QR, ZIP Backup, ZIP XLSX для
   реестра. Архивы инвентаризации в папку `Inventorization` внутри папки проекта;
   для утечек завести родительскую `Leaks` с `zip_backup`, `zip_xlsx` и прочим.
4. **Геолокация как в форме утечки** — см. дыру выше.
5. **Компоненты на карте** — переключатель Leaks/Components кнопкой на карте,
   чтобы координаты не смешивались; кнопки карты меняются по активной базе.
6. **Панель фильтров как на странице базы** — глобальный фильтр шапки уже
   подключён; добавить строку поиска с кнопкой фильтра, чипы, панель результатов,
   сортировку, массовый выбор, XLSX.
7. **Довести подробную карточку** — вкладки Фото / Координаты / Параметры (бирка,
   номер на схеме, диаметр, давление, температура, среда); координаты в просмотре
   и правке; иконка корзины вместо кнопки Delete с диалогом как в LeakForm;
   правка не открывает форму создания заново; миниатюра открывается как в
   LeakForm; в истории показывать прежнее и новое значение, а не имя поля.
8. **Список и схемы** — gap между карточками; `VirtualizedList` для схем;
   полноэкранная модалка схем; починить «Браузер заблокировал новую вкладку» на
   PDF.
9. **Подсказки и голос** — `GhostPlaceholder` из предыдущей записи при создании
   следующего компонента; починить голосовой ввод.
10. **Даты без времени** — во всех режимах просмотра только дата; время остаётся
    в данных и уходит в Excel.

## 7. Правила работы с этим репозиторием

- Перед коммитом гонять весь набор из шапки этого файла. Есть хук `lint-staged`.
- **Бюджет сборки реальный.** `npm run check:bundle` падает, а не предупреждает.
  Индексный чанк уже на 98% лимита — тяжёлое в стартовый граф не класть.
- Локали `ru` и `en` проверяются на паритет ключей (`locales.test.js`).
- Страницы объявляются в `src/app/pages.js`: `APP_PAGES` (иначе переход молча
  уводит на главную), `LIST_PAGES` (оболочка пинится к вьюпорту),
  `FULL_SCREEN_PAGES` (шапка и навигация скрываются). Тест не даёт объявить
  страницу одновременно списочной и полноэкранной.
- Отвечать по-русски.
