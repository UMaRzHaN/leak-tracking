# Handoff: редизайн Leak Tracker (мобильное приложение)

## Обзор
Редизайн полевого приложения учёта утечек: онбординг, главный экран мониторинга, бургер-меню, обход и карточка утечки, карты модулей, инвентаризация и сверка, ремонты и приёмка МТР, экспорт, импорт, настройки проекта.

Работа ведётся в отдельной ветке:
```
git checkout -b redesign
```

## О файлах
Файлы в `designs/` — **макеты в HTML**, референс внешнего вида и поведения. Это не продакшен-код, переносить его нельзя. Задача — воссоздать экраны в существующем стеке `leak-tracking`:
- React 19 + Vite, Capacitor 8 (Android)
- стили — CSS Modules (`*.module.scss`) рядом с компонентом;
- строки — через `react-i18next` (`src/i18n.js`), без хардкода текста в JSX;
- карты — Leaflet + markercluster (`src/pages/MapPage`);
- навигация — `src/app/pages.js` (`APP_PAGES`, `FULL_SCREEN_PAGES`, `LIST_PAGES`). Новый экран без записи в `APP_PAGES` молча уводит на главную.

Как открыть макеты: `designs/redesign.dc.html` в браузере. Нужен локальный сервер, например `npx serve designs`. Это холст: экраны сгруппированы по турнам (секции `t1`…`t11`), у каждого экрана есть id (`5e`, `7c` …).

## Точность
**Hi-fi.** Цвета, размеры, радиусы и тексты финальные. Данные в примерах условные: номера кустов, счётчики, расстояния. Если в коде уже есть подходящий токен или компонент (`MobileSheet`, `ConfirmSheet`, `StatusBadge`, `PageHeader`, `Footer`), используйте его и подгоняйте под макет. Параллельных компонентов не заводите.

## Порядок внедрения
Делайте по модулю за раз, каждый модуль — отдельным коммитом или PR в ветку `redesign`:
1. Базовые токены и шрифт (Manrope) → `src/index.scss`
2. Главный экран + бургер-меню (2b, 3a)
3. Утечки: мониторинг, обход, проверка, карта, карточка (5a–5e)
4. Ремонты и приёмка (7a–7i)
5. Инвентаризация и сверка (6a–6d)
6. Экспорт, импорт, настройки (8, 9, 11)
7. Онбординг (1c) и «Обследовано без утечек» (4a–4c)

После каждого шага: `npm run lint && npm test && npm run typecheck`. В e2e (`e2e/`) обновите селекторы, которые затронул редизайн.

## Поведение
- **Нижнее меню у каждого модуля своё** (утечки / ремонты / инвентаризация). Центральная кнопка строит маршрут обхода.
- **Лист маршрута**: переключатель набора точек, список по порядку обхода. Навигация только внутри приложения, выбора внешнего навигатора нет.
- **Плашка маршрута на карте 5d**: «Маршрут · точка N из M», название цели, расстояние, сплошная полоса прогресса и подпись «осталось K». Точек может быть больше 100, поэтому сегментов нет. Тап открывает карточку текущей точки.
- **Фильтры-чипы по статусу на карте 5d убраны.** На остальных картах они остаются.
- Шторки (`MobileSheet`) снизу: радиус сверху 20px, затемнение фона.
- Минимальная зона нажатия — 44px. Основные кнопки — от 54px в высоту.

## Дизайн-токены
Шрифт экранов: **Manrope** 400–800 (`'Golos Text'` и моноширинный — только для подписей холста, в приложение не переносить).

Цвета (по частоте использования):
- Текст: `#0f172a` основной, `#1a1a2e` заголовки, `#505d70` / `#5d718d` вторичный, `#8b87a0` / `#a8a4bb` / `#94a3b8` третичный
- Акцент (фиолетовый): `#6d3de8` основной, `#4b21c4` текст и нажатое состояние, фоны `#f5f2fe` / `#f4f2fa` / `#efedf6`
- Границы и поверхности: `#e2e8f0`, `#e9e6f2`, `#eef2f6`, `#f8fafc`, `#faf9fd`, `#fbfbfd`, `#fff`
- Статусы: успех `#0b7f58` / `#047f59` / `#05875f` на `#ecfdf5`; предупреждение `#a85c05` / `#b26205` на `#fffbeb`; ошибка `#d92323` на `#fef2f2`; инфо `#1d5dea`

Радиусы: 999px (чипы, пилюли), 20px (шторки, крупные карточки), 16px (карточки, плашки на карте), 13–14px (кнопки, поля), 10–12px (иконки-плитки), 5–8px (мелкие бейджи).

Тени: плавающие элементы на карте — `0 6px 20px rgba(15,23,42,.14)`.

Проверьте контраст с `src/index.contrast.test.js`. Новые пары цветов добавьте в этот тест.

## Ассеты
