# Исправления логики импорта/экспорта проекта

## Проблема
При импорте zip-файла резервной копии проекта данные копировались в текущий проект без проверки типа проекта. Это позволяло смешивать несовместимые данные (например, upstream в midstream).

## Решение

### 1. Улучшена обработка импорта с метаданными
**Файл**: `src/services/export/backup.js`
- Функция `buildProjectBackupZip()` уже правильно сохраняет метаданные проекта (название, тип, переменные)
- Функция `peekBackupZip()` уже парсит эти метаданные
- **Не требует изменений** - работает корректно ✓

### 2. Улучшена логика выбора в Settings.jsx
**Файл**: `src/pages/Settings/Settings.jsx`

Обновлена функция `handleImportZip()`:

**Сценарий 1: Файл содержит метаданные (`project.json`)**
- Парсит название и тип проекта из архива
- Показывает подтверждение с названием и кол-вом записей
- **Автоматически создает новый проект** с сохраненным типом
- Импортирует данные и фото в новый проект
- Восстанавливает переменные вычислений (`vars`) если были сохранены

**Сценарий 2: Файл НЕ содержит метаданные (старые резервные копии)**
- Показывает диалог с двумя вариантами:
  - **OK** = Создать новый проект
    - Пользователь вводит название
    - Выбирает тип проекта (Upstream/Midstream)
    - Создается проект с выбранным типом
  - **ОТМЕНА** = Импортировать в текущий
    - Требует выбранный активный проект
    - Показывает подтверждение и название проекта назначения
    - Импортирует данные в текущий проект

### 3. Удалена неиспользуемая функция
- Функция `handleImportZipLegacy()` была удалена (она не вызывалась нигде)
- Вся логика теперь сосредоточена в одной `handleImportZip()`

### 4. Исправлены зависимости
- Добавлен `activeProject` в массив зависимостей `handleImportZip()`
- Это обеспечивает корректное получение текущего проекта в контексте импорта

## Результат
✓ При импорте файла с метаданными проект создается с правильным типом
✓ При импорте файла без метаданных пользователь явно выбирает целевой проект
✓ Невозможно случайно смешать несовместимые типы данных
✓ Все фото и переменные корректно восстанавливаются

## Тестирование
```bash
npm run build  # ✓ успешна компиляция без ошибок
```

Файл успешно компилируется с новой логикой.
